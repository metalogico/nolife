# Installation and operations

The [README](../README.md#install-with-docker-compose) covers a fresh installation. Run the commands below from the directory containing the downloaded `compose.yaml` and your private `.env`. The default stack pulls a versioned GHCR image.

## Requirements

- Docker Engine and the current Docker Compose plugin, or Docker Desktop with Compose.
- Internet access for the initial image pull, and sufficient disk space for images, your collection and retained backups.
- A free host port; the default is 8093. A modern browser is needed for the custom dropdowns and dialogs.

The Dockerfile builds the frontend with Node 24 and installs production PHP dependencies with Composer. Its base images are pinned by digest; `composer.lock` and `package-lock.json` fix application dependency versions. OS packages come from the base distribution's configured repositories. The runtime contains PHP 8.4, Apache, SQLite, GD/WebP and PCNTL. Docker Compose supplies an init process and SIGTERM handling for the worker and scheduler.

## Configuration

Copy `.env.example` to `.env` and follow the README to generate the application key and password hash. Do not start with the example placeholders. A Docker helper command bypasses the normal entrypoint while generating credentials; startup checks and migrations run when you start the application.

| Variable | Purpose |
| --- | --- |
| `APP_KEY` | Persistent Laravel encryption key; generate once and keep it with recovery configuration |
| `NOLIFE_USERNAME` | The single account's username |
| `NOLIFE_PASSWORD_HASH` | Bcrypt hash generated by `nolife:password`, enclosed in single quotes |
| `NOLIFE_BIND_IP` | Host listening address; default `127.0.0.1` |
| `NOLIFE_PORT` | Host HTTP port; default `8093` |
| `NOLIFE_URL` | Complete URL used to access NoLife, including a nonstandard port |
| `APP_TIMEZONE` | Application and scheduled backup timezone; default `Europe/Rome` |
| `SESSION_SECURE_COOKIE` | Set to `true` when the browser accesses NoLife over HTTPS |
| `IGDB_CLIENT_ID`, `IGDB_CLIENT_SECRET` | Optional credentials for metadata search and matching |

Compose explicitly sets production mode, disables debug output, and selects SQLite, file sessions/cache and the database queue. It sets the internal database and backup paths; leave those paths as provided. `APP_URL` is set from `NOLIFE_URL` inside the containers.

After editing `.env`, recreate all services so the app, worker and scheduler receive the same settings:

```sh
docker compose up -d --force-recreate --wait
```

Changing the username, password hash or application key invalidates authenticated sessions. Preserve `APP_KEY` across routine updates and recovery. To change the password, run the README's interactive `nolife:password` helper again, replace the quoted hash in the host `.env`, and recreate the services. Do not use `--write` inside the container: `.env` is supplied as environment variables and is not mounted into the image.

## LAN access and HTTPS

For access from other devices, set `NOLIFE_BIND_IP` to the server's LAN address and `NOLIFE_URL` to its reachable URL, for example `http://games.home:8093` when that name resolves to your server. Check the host firewall for the chosen port.

For HTTPS, place a reverse proxy in front of Apache, configure its upstream to the mapped HTTP port and set `NOLIFE_URL=https://your-hostname` and `SESSION_SECURE_COOKIE=true`. TLS termination and hostname/certificate management are supplied by your reverse proxy. The Compose stack serves HTTP internally.

## Services and persistence

| Service | Role | Memory limit |
| --- | --- | --- |
| `app` | Apache/PHP API, UI, startup migrations and configuration cache | 512 MB |
| `worker` | Image downloads and WebP conversion, with retry handling | 256 MB |
| `scheduler` | Scheduled database and media backups | 128 MB |

These are container limits rather than a complete host sizing estimate; image builds also need memory. All services restart with `unless-stopped`. Only `app` exposes a port. The worker and scheduler wait for the app health check at `/up` before starting.

The default project name is `sh-nolife`; Compose prefixes the data, storage and backups volumes with it. SQLite uses foreign keys, WAL and a five-second busy timeout. The shared library lock coordinates app and worker mutations with backup snapshots.

- `data` is mounted at `/var/lib/sh-nolife` and contains the SQLite database, WAL and shared-memory files.
- `storage` is mounted at `/var/www/html/storage` and contains private images, file sessions/cache, logs and the library lock.
- `backups` is mounted at `/backups` in the app and scheduler.

Startup prepares writable directories and assigns them to the container's `www-data` user (UID/GID 33). A backup bind directory must support these permissions. The web container starts as root to prepare storage and start Apache; Apache requests, the worker and scheduler run as `www-data`.

```sh
docker compose ps
docker compose logs --tail 50 app worker scheduler
docker compose stop
docker compose up -d --wait
```

Stopping or recreating containers preserves volumes. `docker compose down` also retains the named volumes; `docker compose down -v` deletes the collection, media and default backups and must not be used for updates.

### Separate installations

Use a different Compose project name, port, environment file and image tag for an isolated instance. This is also useful for installation checks without accessing an existing library.

In a separate private environment file copied from `.env.example`, set fresh credentials and:

```dotenv
NOLIFE_ENV_FILE=/absolute/path/to/test.env
NOLIFE_IMAGE=ghcr.io/metalogico/nolife:latest
NOLIFE_PORT=18093
NOLIFE_URL=http://localhost:18093
```

```sh
docker compose --env-file /absolute/path/to/test.env -p nolife-test pull
docker compose --env-file /absolute/path/to/test.env -p nolife-test up -d --wait
```

`--env-file` supplies Compose interpolation values; `NOLIFE_ENV_FILE` selects the file injected into every service. Both are needed to avoid reading another instance's `.env`. Keep using the same options for every command against that instance. Its volumes are `nolife-test_data`, `nolife-test_storage` and `nolife-test_backups`.

## Updates

Follow [UPGRADING.md](UPGRADING.md). Keep `.env`, `APP_KEY` and persistent volumes; back up and export before changing versions. Pull the selected image, stop all services including the worker/scheduler, and recreate. The app migrates before becoming healthy. A schema-changing rollback requires its matching backup.

## Backup and restore

A backup contains a standalone SQLite snapshot, its SHA-256 manifest and all locally stored game media. The snapshot includes committed WAL data through `VACUUM INTO`; the shared library lock keeps the snapshot and media consistent during creation. The manifest verifies the database hash and SQLite integrity before recovery. `.env` and application sources are not included.

Create a backup as `www-data`:

```sh
docker compose exec -T --user www-data app php artisan nolife:backup --no-interaction
```

The command prints `/backups/nolife-TIMESTAMP-RANDOM.tar.gz`. Files use mode 0600. Substitute that exact filename when copying the archive to your host:

```sh
docker compose cp app:/backups/ARCHIVE.tar.gz ./ARCHIVE.tar.gz
chmod 600 ./ARCHIVE.tar.gz
```

Move the exported archive to separate storage, together with a protected copy of `.env` and the matching application source revision. The scheduler creates backups at 03:30 and 15:30 in `APP_TIMEZONE`; no automatic archive pruning is configured. Monitor free space and the scheduler's logs.

### Backups on a separate disk

The optional `compose.minipc.yaml` override replaces `/backups` with a bind mount. Despite its filename, it is usable on any Docker host. Prepare an existing directory on the intended mounted disk, with access for UID/GID 33. The app entrypoint adjusts ownership within that directory.

Download the override into the installation directory:

```sh
curl -fL https://raw.githubusercontent.com/metalogico/nolife/main/compose.minipc.yaml -o compose.minipc.yaml
```

Add these values to your private `.env`:

```dotenv
COMPOSE_FILE=compose.yaml:compose.minipc.yaml
NOLIFE_BACKUP_DIR=/absolute/path/on/backup-disk/nolife
NOLIFE_BACKUP_VOLUME_ID=your-chosen-disk-marker
```

Create a file named `.volume-id` in that directory containing the exact `NOLIFE_BACKUP_VOLUME_ID` value. Backup creation fails when the sentinel is missing or different, helping detect an unavailable backup disk. The bind mount uses `create_host_path: false`, so Compose will not silently create a missing directory. Recreate the services after changing this configuration.

On Windows, use the platform's Compose file separator or pass `-f compose.yaml -f compose.minipc.yaml` explicitly. Keep using the override for subsequent operations.

### Verify without changing the collection

Use a new or empty directory for each isolated verification:

```sh
docker compose exec -T --user www-data app php artisan nolife:restore /backups/ARCHIVE.tar.gz --to=/tmp/nolife-restore-check --no-interaction
```

The command validates and extracts the archive into that directory. It does not replace the current collection.

### Restore the active collection

Take and export a current backup first. Stop both background services and enter maintenance mode before replacing the library:

```sh
docker compose stop worker scheduler
docker compose exec -T --user www-data app php artisan down --no-interaction
docker compose exec -T --user www-data app php artisan nolife:restore /backups/ARCHIVE.tar.gz --force --no-interaction
docker compose exec -T --user www-data app php artisan migrate --force --no-interaction
docker compose exec -T --user www-data app php artisan up --no-interaction
docker compose start worker scheduler
```

Run each command only after the previous command succeeds. If restore or migration fails, keep maintenance mode enabled and the background services stopped while you investigate. Live restore verifies the archive before replacing the database and media; it requires both maintenance mode and `--force`.

To recover onto a fresh Docker host, restore the protected `.env` (including its original `APP_KEY`), pull and start the matching image version, copy the archive into `/backups` with `docker compose cp`, then follow the live restore procedure. Ensure the copied archive is readable by `www-data`. A restore reuses the data and storage volumes; it replaces the current library and images.

## Troubleshooting

- **App exits with an APP_KEY error:** generate the key with the README helper, put it in the host `.env`, and recreate the services.
- **Sign-in is unavailable or the password fails:** check the username and the entire single-quoted hash line, then recreate all services. The password must be hashed with the provided command.
- **Images remain pending:** inspect `docker compose logs --tail 100 worker`; check outbound access to IGDB and available disk space.
- **IGDB is unavailable:** manual entry remains available. Check your own client credentials and follow the provider's [current setup instructions](https://api-docs.igdb.com/#account-creation).
- **Backups fail:** check free space, directory permissions and the `.volume-id` sentinel if configured. Inspect app and scheduler logs.
