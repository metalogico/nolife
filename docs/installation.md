# Installation and operations

For a fresh installation, follow the [README](../README.md#install-with-docker-compose). Run the commands below from the directory containing `compose.yaml` and your private `.env`.

## Requirements

- Docker Engine and the current Docker Compose plugin, or Docker Desktop with Compose.
- Internet access for the initial image pull, and sufficient disk space for images and your collection.
- A free host port; the default is 8093.
- A modern browser.

## Configuration

Copy `.env.example` to `.env` and follow the README to generate the application key and password hash.

| Variable | Purpose |
| --- | --- |
| `APP_KEY` | Persistent Laravel encryption key; generate once and preserve across container recreations |
| `NOLIFE_USERNAME` | The single account's username |
| `NOLIFE_PASSWORD_HASH` | Bcrypt hash generated by `nolife:password`, enclosed in single quotes |
| `NOLIFE_BIND_IP` | Host listening address; default `127.0.0.1` |
| `NOLIFE_PORT` | Host HTTP port; default `8093` |
| `NOLIFE_URL` | Complete URL used to access NoLife, including a nonstandard port |
| `APP_TIMEZONE` | Application timezone; default `Europe/Rome` |
| `SESSION_SECURE_COOKIE` | Set to `true` when the browser accesses NoLife over HTTPS |
| `IGDB_CLIENT_ID`, `IGDB_CLIENT_SECRET` | Optional credentials for metadata search and matching |

Compose sets production mode, SQLite, file sessions/cache and the database queue. `APP_URL` is set from `NOLIFE_URL` inside the containers.

MCP access and keys are managed in [Settings](mcp.md#manage-mcp-in-settings).

After editing `.env`, recreate both services so the app and worker receive the same settings:

```sh
docker compose up -d --force-recreate --wait
```

Changing the username, password hash or application key invalidates authenticated sessions. Preserve `APP_KEY` across routine updates. To change the password, run the README's interactive `nolife:password` helper again, replace the quoted hash in the host `.env`, and recreate the services. Do not use `--write` inside the container: `.env` is supplied as environment variables and is not mounted into the image.

## LAN access and HTTPS

For access from other devices, set `NOLIFE_BIND_IP` to the server's LAN address and `NOLIFE_URL` to its reachable URL, for example `http://games.home:8093` when that name resolves to your server. Check the host firewall for the chosen port.

For HTTPS, place a reverse proxy in front of Apache, configure its upstream to the mapped HTTP port and set `NOLIFE_URL=https://your-hostname` and `SESSION_SECURE_COOKIE=true`. TLS termination and hostname/certificate management are supplied by your reverse proxy. The Compose stack serves HTTP internally.

## Services and persistence

| Service | Role | Memory limit |
| --- | --- | --- |
| `app` | Apache/PHP API, UI, startup migrations and configuration cache | 512 MB |
| `worker` | Image downloads and WebP conversion, with retry handling | 256 MB |

Both services restart with `unless-stopped`. Only `app` exposes a port. The worker waits for the app health check at `/up` before starting.

The default project name is `sh-nolife`; Compose prefixes volume names with it.

- `data` is mounted at `/var/lib/sh-nolife` and contains the SQLite database, WAL and shared-memory files.
- `storage` is mounted at `/var/www/html/storage` and contains private images, file sessions/cache, logs and the library lock.

Startup prepares writable directories and assigns them to the container's `www-data` user (UID/GID 33). The web container starts as root to prepare storage and start Apache; Apache requests and the worker run as `www-data`.

```sh
docker compose ps
docker compose logs --tail 50 app worker
docker compose stop
docker compose up -d --wait
```

Stopping or recreating containers preserves volumes. `docker compose down` also retains the named volumes; `docker compose down -v` deletes the collection and media and must not be used for updates.

### Separate installations

Use a different Compose project name, port and environment file for an isolated instance.

In a separate private environment file copied from `.env.example`, set fresh credentials and:

```dotenv
NOLIFE_ENV_FILE=/absolute/path/to/test.env
NOLIFE_IMAGE=ghcr.io/metalogico/nolife:latest
NOLIFE_PORT=18093
NOLIFE_URL=http://localhost:18093
```

```sh
docker compose --env-file /absolute/path/to/test.env -p nolife-test pull
docker compose --env-file /absolute/path/to/test.env -p nolife-test up -d --wait
```

`--env-file` supplies Compose interpolation values; `NOLIFE_ENV_FILE` selects the file injected into every service. Both are needed to avoid reading another instance's `.env`. Keep using the same options for every command against that instance. Its volumes are `nolife-test_data` and `nolife-test_storage`.

## Troubleshooting

- **App exits with an APP_KEY error:** generate the key with the README helper, put it in the host `.env`, and recreate the services.
- **Sign-in is unavailable or the password fails:** check the username and the entire single-quoted hash line, then recreate all services. The password must be hashed with the provided command.
- **Images remain pending:** inspect `docker compose logs --tail 100 worker`; check outbound access to IGDB and available disk space.
- **IGDB is unavailable:** manual entry remains available. Check your own client credentials and follow the provider's [current setup instructions](https://api-docs.igdb.com/#account-creation).
